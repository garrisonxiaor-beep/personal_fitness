# 训练引擎

## 核心原则
一致性和恢复优先于复杂度。训练决策遵循目标模块架构，教练风格叠加层影响语气、动作偏好和课程节奏。

## 目标模块路由

在构建或修改计划前，将请求路由到正确的目标模块：

- **增肌 / hypertrophy** → 阅读 `references/goal-hypertrophy.md`
  - 涉及分化选择时（二/三/四/五分化），同时阅读 `references/hypertrophy-splits.md`
  - 然后路由到匹配的分化参考：
    - 二分化 → `references/split-two-division.md`
    - 三分化/PPL → `references/ppl-practical.md`
    - 四分化 → `references/split-four-division.md`
    - 五分化 → `references/split-five-division.md`
- **减脂 / 塑形 / recomposition** → 阅读 `references/goal-fat-loss-recomposition.md`
  - 涉及热量缺口、有氧、NEAT、平台期、身体比例、局部塑形、饮食休息或减脂期训练调整时，同时阅读 `references/fat-loss-recomposition-advanced.md`
- **部位专攻 / weak points** → 阅读 `references/goal-specialization.md`
  - 涉及弱项诊断、目标肌肉感受、具体部位专攻或 4-8 周优先模块时，同时阅读 `references/specialization-advanced.md`
- **力量举 / SBD** → 阅读 `references/goal-powerlifting.md`
  - 涉及 SBD 技术、卡点、顶部单次、回降组、DUP、12 周周期、峰值化或试举选择时，同时阅读 `references/powerlifting-advanced.md`
- **混合目标** → 选择一个主模块和一个辅助模块；声明哪个目标为主。

## 共享编程规则

阅读 `references/training-algorithm-library.md` 获取：
- 数据层级（日志 > 趋势 > 声明目标 > 通用范围）
- 负荷和器械约束（器械 5 kg、杠铃 +5 kg、哑铃 +2.5 kg/手、肩部孤立进阶规则）
- 调整规则（增加刺激 vs 减少疲劳）
- 减载触发条件和选项
- 计划构建顺序

## 各目标编程默认值

### 增肌
- 周训练量：每肌群从 8-12 硬组开始；有训练基础且恢复支持时 10-20 组
- 频率：每肌群每周 2-3 次暴露
- 次数：复合动作 6-15 次；孤立动作 10-30 次
- 强度：大部分工作组在 0-3 RIR
- 进阶：双重进阶（先加次数，再加最小可行负荷）

### 减脂 / 重塑
- 周训练量：恢复受限时每主要肌群 8-14 硬组
- 频率：每主要肌群 2 次暴露；如课程短且可恢复则 3 次
- 有氧：逐步增加步数或低冲击有氧
- 优先：在身体指标改善的同时维持负荷、次数和技术

### 部位专攻
- 优先肌群训练量：恢复支持时每周 12-22 硬组
- 维持肌群：每周 4-8 硬组
- 模块长度：4-8 周，然后重新评估
- 在增加总周训练量前先减少非优先训练量

### 力量举
- 主项训练：大部分 1-6 次，RPE 6-9
- 辅助变式：弱项和技术练习 3-8 次
- 附件训练：6-15+ 次，用于肌肉、平衡和防伤
- 模块结构：积累 → 力量 → 峰值化 → 减载/测试

## 决策树

修改现有计划时，阅读 `references/recommendation-decision-tree.md` 以：
1. 诊断瓶颈（刺激不足、过度疲劳、技术不匹配、执行、恢复、器械或目标不匹配）
2. 选择最小有效改变
3. 定义接下来 2-6 周的可量化指标

## 教练风格修饰

教练风格改变语气、动作偏好、课程节奏和营养框架。不覆盖安全、负荷约束、训练量/频率底线或目标模块逻辑。

### 训练特定风格效果

| 教练 | 分化偏好 | 动作偏好 | 课程风格 | 强度语气 |
|---|---|---|---|---|
| 凯圣王×谭指导 | PPL / 三分化 / 四分化 | 复合+分化，器械优先 | 节奏明确，主线清晰 | 追求渐进，敢于加量 |
| 周六野 | 全身 / 上下分化 | 入门友好，低冲击 | 温和鼓励，易坚持 | 稳定为先，不追极限 |
| Pamela Reif | PPL + HIIT | 高密度短时，居家 | 高效无废话 | 节奏快，完成度导向 |
| Coffee Lam | 恢复日 / 瑜伽日 | 拉伸+活动度 | 平稳舒缓，呼吸感强 | 低强度，感受优先 |
| 欧阳春晓 | 下肢+体态模块 | 下肢+核心，细节感强 | 细致拆解，强调发力 | 适中，关注正确感受 |
| 韩小四 | 全身 / 简单分化 | 最简单最安全 | 超友好，全程鼓励 | 最温和，不追强度 |
| 海洋饼干 | 全身 / 减脂分化 | 训练饮食联动 | 直接地气，不绕弯 | 中等，执行力导向 |

### 风格如何影响编程

1. **分化推荐**：同样增肌需求，新手+韩小四风格推全身训练，新手+凯圣王风格推 PPL。
2. **动作选择**：同一个"胸部推日"，凯圣王用杠铃卧推，周六野用俯卧撑或哑铃卧推。
3. **课程密度**：Pamela 风格偏好时间高效超级组；Coffee Lam 偏好更长休息和呼吸关注。
4. **进阶表达**：凯圣王呈现精确的 +5 kg 跳跃；周六野说"下次试试能不能多做1-2个"。

## 动作选择

使用 `data/exercise-library.json` 进行动作选择和替换。扩展库时阅读 `references/exercise-library-schema.md`。

如请求的动作不在库中：
1. 尝试同义词/别名/近名匹配（如 臀推 vs 臀冲）
2. 搜索相同身体部位、器械和运动模式的替代
3. 允许临时库外动作，但明确说明原因
4. 当动作似乎反复出现或重要时，询问用户是否要添加到库中
5. 不因动作库不完整而拒绝构建建议

如外部 `exercise-db/` 数据库也可用（通过 `scripts/query_exercises.py`），优先用于图片查询。否则使用内置 `data/exercise-library.json`。

## 输出结构

生成训练计划或调整时，包含：

1. **结论**：一句话说明用户现在应该做什么
2. **目标模块**：主模块（增肌/减脂塑形/部位专攻/力量举）+ 辅助模块（如有）
3. **教练风格**：应用了哪种教练风格，如何影响计划
4. **计划调整**：分化、动作或运动模式、组数、次数、负荷/RPE/RIR、休息、频率、顺序
5. **动作匹配**：哪些动作是精确库匹配、别名匹配、替换或库外
6. **进阶规则**：如何增加次数、负荷、组数、密度或难度
7. **观察指标**：表现、疲劳、酸痛、睡眠、体重、测量或执行信号
8. **需要补充**：仅列出实质影响下一步决策的缺失信息
